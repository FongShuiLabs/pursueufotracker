PURSUE Changes Log

FIRST PUBLISHED 20 MAY 2026 · UPDATED 13 OCT 2026 · COUNTED FROM THE RAW CSV

What this page contains. Every change to war.gov's PURSUE CSV that we can document, from the first release on May 8 to today's 450-row file (Release 06, revised September 18 and 24). It has a row-by-row diff of Releases 03 to 06 computed from the raw CSV rows, a timeline of every CSV state our poller recorded, one card per release, and the original May 11 comparison (161 to 158 rows) further down. Each claim on this page is a direct count. No interpretation of war.gov's intent: we say what changed, not why. No characterizations of "renames," "consolidations," or "reclassifications" - those would be inferences and are kept off this page. Where we cannot reproduce something, the page says so.

Headline findings: (1) No row has been removed. In each of the three steps from Release 03 to Release 06, zero rows were removed, and none of the 294 rows in the Release 03 CSV is missing today. (2) War.gov does edit existing rows after publishing: 31 rows across those three steps, 29 of them by clearing the "Featured" flag. (3) Release 06's CSV first appeared at 446 rows in total (71 of them new), grew to 447 four hours later, and to 450 six days later. (4) The May 11 revision, covered below, added and removed no files: zero PDFs and zero videos in either direction.

Three things in the CSV itself

  • The Featured flag is only ever set on the newest release's rows. In each of the four CSVs the flag is set only on rows from that CSV's own latest release (10 rows in Release 03, 10 in Release 04, 9 in Release 05, 10 in Release 06). In each next release, every row flagged in the previous one was cleared (10 of 10, 10 of 10, 9 of 9). We do not know why; the pattern is a count, not an explanation. The flag's values are also not consistently cased ("YES" and "Yes" both appear).
  • Two new agency labels, one per release. Release 05 introduced "Executive Office of the President" (1 row: EOP-UAP-D001). Release 06 introduced "Local Law Enforcement" (8 rows). Release 04 introduced none, and relabelled the one row that said "Central Intelligence Agency" to "CIA", so the current CSV uses a single label for CIA records (23 rows).
  • One ID is used for two different documents. Since Release 04, the ID FBI-UAP-D014 is carried by two rows with different files: a Release 03 image titled "Digital Rendering, Narrative Statement 1-1, Western United States Event" and a Release 04 PDF titled "Correspondence Relating to UFO Sightings, 1967, 1974". Anyone joining on the ID alone will merge them. We match on the ID plus the file link.

🔬 File-integrity audit · war.gov re-processed 62 documents · verified: no content removed

Sometime between our May 8-9 capture and June 10, war.gov silently replaced the file bodies of 62 Release-01 PDFs at the same URLs - same filenames, same CSV rows, same page count. The replacement files are about half the size (the audited corpus went from 2.49 GB to 1.25 GB). A CSV-row poller cannot see this, because the CSV did not change. This was first flagged publicly by a reader hashing every file daily; we independently verified it before publishing, and credit the catch. The natural worry - "they shrank the files, are they hiding something?" - is answerable here because we keep the original bytes.

What we verified, file by file, against our archived originals (all 62):

Pages preserved62 / 62
Pages removed0
Images cropped0
OCR text added~32 scans

Conclusion: re-processing, not removal. War.gov re-compressed the raw scanned images and added searchable OCR text layers. The originals had no extractable text (they were image-only scans); the new versions are text-searchable. The files got smaller and more usable. We checked every one of the 62 changed files - page counts are identical, and the single file that showed fewer extracted characters turned out to be garbage OCR being replaced with clean text, not content loss.

Scope of this claim: we compared page counts and extractable-text layers on all 62 changed files against our SHA-256-matched originals. We did not pixel-compare every page image, so we cannot rule out a localized visual change on an individual page - but no pages were dropped, no images cropped, and OCR text was added rather than removed. The exact date of the swap is bounded by our two data points (May 8-9 and June 10); a reader with daily snapshots dates it to mid-May. Full machine-readable per-file audit (old size, old SHA-256, current size): wargov-file-integrity-audit-2026-06-10.json.

The May 11 revision (161 to 158 rows)

TL;DR (plain English)

War.gov changed how they label their UFO file list on May 11, 2026, but the files themselves are exactly the same. 130 PDFs and 28 videos exist in both versions. The row count in their published spreadsheet dropped from 161 to 158 because 9 PDFs that used to appear as one row each now appear as multiple rows (the same file referenced under different incident titles), and one PDF had its storage filename renamed. The arithmetic

The row-count delta of -3 (161 May 8 rows -> 158 current rows) decomposes cleanly:

May 8 CSV: 161 rows = 130 unique PDFs + 16 video rows + 15 PDF rows that were duplicates within the May 8 file = 130 PDF URLs + 28 video DVIDS IDs in the unique set May 11+ CSV: 158 rows = 130 unique PDFs + 16 video rows + 12 additional cross-reference PDF rows = 130 PDF URLs + 28 video DVIDS IDs in the unique set (same unique set after accounting for 1 PDF slug change; see Table 2 below) Net delta: -3 rows = 15 historical PDF-row duplicates - 12 new cross-reference rows = -3

The unique-file inventory between the two dates is identical. The CSV structure changed; the file set did not.

How to verify this page yourself

Anyone can re-run the diff. The inputs are public:

  1. Current war.gov CSV: war.gov/Portals/1/Interactive/2026/UFO/uap-csv.csv (warm a session at war.gov/UFO/ first or the CDN will 403)
  2. May 8 manifest snapshot: /generated/api/files.json (our parsed copy; the original war.gov May 8 CSV is no longer hosted but its SHA-256 is preserved in our poll-state history)
  3. The diff itself: extract the PDF | Image Link column from the CSV, normalize to lowercase, set-difference against the source_url field from our manifest. The result will match the May 11 tables on this page.

Re-running the Release 03 to 06 diff

The row-by-row figures come from pipeline/release_diff.py. Clone the repository and run python -m pipeline.release_diff. It reads one CSV per release out of public git history, writes data/release-diff.json, and should reproduce every count above. The four copies are the versions of data/uap-data.csv at commits 72463170 (Release 03), e25c27c1 (Release 04), 3db64f7a (Release 05) and 189e0919 (Release 06).

Two limits. First, the Release 05 and 06 copies are byte-identical to what war.gov served (their SHA-256 match our poller's record), but the Release 03 and 04 copies were committed before we pinned line endings on July 12, so their bytes differ from war.gov's and the diff uses their parsed rows. For Release 03 we compared those rows with our byte-exact copy (SHA-256 48db08be...) and they are identical. For Release 04 we have no byte-exact copy, so that step rests on the committed rows. Second, we only have CSV copies for these four releases. The other states in the timeline above were recorded by hash and row count only.

Why this page exists

An earlier version of /revisions characterized the May 11 change as including removals, additions, geographic consolidation, and reclassification. None of those characterizations are supported by the URL-set comparison. Rather than silently rewriting and pretending the mistake didn't happen, we kept the correction visible on /revisions and built this page to host the verified data tables. Per the site's editorial policy, transparency about our own errors is part of the credibility moat.
